# 边际分析: 效用递减 / 边际成本 / 边际利润

## R — Reading (原文)

> "边际利润是指在一个给定约束条件下, 再多做一笔交易, 增加的额外利润。这个概念对产品很重要。" (3.3.3)
> "比如制造业企业, 其生产的时候一开始有规模效应, 边际成本是逐步降低的。但到了某一个临界点后, 其边际成本反而有可能会变高。" (3.3.2)
> "以网约车出行行业……成交一单, 17~18 元都是要给司机的边际成本, 企业只能拿到 3 元左右的边际收入。" (3.3.3)

## I — Interpretation (自述)

用"再多一单位"的视角看产品与生意: 边际效用递减 (第 1 个苹果与第 6 个、第 1 个千万与第 N 个千万的满足感不同, 程度因人而异); 边际成本先降后升 (规模效应到临界点后, 原料加价、边际组织成本、获客成本递增——互联网获客同理, 越后转化的用户成本越高); 边际利润 = 边际收入 – 边际成本, 商业模式的弹性由固定/边际结构决定: 网约车单笔给司机 17-18 元、平台留 3 元 (边际成本占比高、利润薄而稳); 共享单车投放后成本固定、多用一单只多少量运维 (边际利润随量放大); 饭店固定成本高、原料仅两三成, 盈亏平衡 280 客时, 300 客净利 20 人份、340 客净利 60 人份——差 13% 客流, 净利差 3 倍。判断生意性质、扩张决策、定价弹性都要看边际结构而非平均数。

## A1 — Application Example (书中案例 / 合成演练)

【书中案例 · worked_example (可复算), 出处 3.3.3】饭店: 需 280 客保本, 客单 100 元, 原料两三成 (取 25%)。300 客净利 = (300-280)×(100-25) = 20×75 = 1500 元; 340 客 = 60×75 = 4500 元 = 3 倍。结论: 经营饭店固定成本高, 客流小幅波动造成净利润剧烈波动。

【书中案例 · firsthand, 出处 3.3.3】网约车: 全职司机模式下, 无论司机基数 10 万还是 100 万, 每单 17-18 元付司机、平台约 3 元边际收入 (其中还有相当比例补贴给司机)——与饭店/共享单车的边际结构完全不同。

【合成演练 (原书未提供, 按其规则构造)】SaaS 订阅: 边际成本≈服务器+客服 (低), 边际利润随订阅数放大 → 增长优先; 但获客成本边际递增 (越后的客户越难转化) → 判断 LTV/CAC 的边际走势决定扩张节奏。

## A2 — Future Trigger (触发情境)

1. 判断生意/商业模式的性质与弹性 ("这是好生意吗""规模大了会更赚还是更亏")
2. 扩张/降价/补贴决策 ("多一单到底赚多少")
3. 客流或用户量波动时的利润敏感性测算
4. 对比不同业务模式的成本结构

语言信号: "边际""规模效应""固定成本""多一单赚多少""获客成本上升""盈亏平衡" (中英: marginal cost, marginal profit, economies of scale, unit economics, break-even)

与相邻能力的区分 (阶段 3 定稿): 本卡是成本利润结构的量级分析; 交易结构设计见 transaction-model-design (本卡为其成本侧工具); 效用端的递减判定见 utility-four-types; 资源投入的均衡点判断两卡配合。与通用单位经济分析的区别: 强调"边际成本先降后升"的非线性与三类原书商业模式对照。

**AI 产品化适配** (AI 适配, 非原书) 追加触发情境: ① "AI 功能每多一个活跃用户要多花多少 token, 量越大越亏吗"——LLM 产品按高边际结构建表; ② "订阅制订阅费包不住推理成本怎么办"——降边际动作与敏感性演算。

## E — Execution (可执行步骤)

输入契约: 一项业务/产品 + 可获得的成本收入结构数据 (粗估可用, 须注明口径)。

1. 拆成本: 列固定成本项 (不随量变) 与边际成本项 (每多一单/一用户增加什么), 标注每项金额或比例与依据。
2. 定边际利润: 边际收入 – 边际成本, 写出单位口径 (每单/每用户/每客); 判定结构类型: 高固定低边际 (饭店/单车/SaaS 型, 量放大利润弹性大) / 高边际 (网约车型, 单笔薄而稳) / 混合。
3. 查边际成本曲线拐点: 规模到哪里开始变贵 (原料/组织/获客递增)? 标注当前量级离拐点远近。
4. 敏感性演算 (可复算): 选两个业务量档位, 分别算净利, 给出"量变动 X% → 利润变动 Y%"的弹性结论。
5. 输出: 边际结构表 (固定/边际/拐点/弹性) + 对扩张或定价决策的含义。

判停点: 数据不足以拆固定/边际 → 输出"结构不明"并列待补数据, 不用平均成本冒充边际成本。

输出契约: 边际结构表+两档演算过程; 完成标准 = 演算可复算 (数字与口径齐备), 拐点有判断或标注不可得。

**AI 产品化适配** 要点 (AI 适配, 非原书):
1. LLM 产品按"高边际"结构建表: 边际成本 = 单用户 token 消耗 × 单价 (随用量近似线性增长), 与传统软件近零边际对照; 分轻重场景列每用户每单位时间的成本。
2. 拐点检查新增技术型拐点: 长上下文/复杂任务使单次成本非线性上升, 标注触发条件与当前量级离拐点远近。
3. 降边际动作逐项写预期降幅与体验代价: 模型分级路由 (简单任务用便宜模型)、缓存与批处理、限制输出长度/轮次。
4. 敏感性演算按"用量 ×2"与"模型换代降价 50%"两档跑, 判断增长能否吃掉成本曲线; 演算标注模型版本与单价时点。
5. 完成标准: 边际结构表含 token 口径与模型版本时点, 两档演算可复算。

## B — Boundary (边界)

- 原书数字 (17-18 元/3 元/280 客等) 为 2019 年前后内部口径, 未经外部核验 (nr-03), 只作结构示例不可引用为现状。
- 边际分析是短周期局部工具: 多边平台的交叉补贴与网络效应会让"单笔边际"失真 (补贴、生态位价值), 结论需配合交易模型视角。
- "边际效用递减"用于效用端判断时因人而异 (作者注明), 不可当普适常数; 与损失厌恶 2.5 倍是不同概念, 勿混用。
- 固定/边际的划分依赖时间尺度: 长期看所有成本都可变, 标注分析周期。
- 相邻易混: 效用满足程度的投入策略见 utility-four-types; 生意结构的利益分配见 transaction-model-design。
- **AI 产品化适配** (AI 适配, 非原书): 不要套用"互联网近零边际"直觉评 AI 产品——推理成本随用量真实发生; 也不要把模型降价趋势外推成"以后总会便宜", 拿来掩盖当下为负的边际利润, 输出须标注时点与模型版本。
