# 交易模型设计: 利从何来, 利往何去

## R — Reading (原文)

> "交易模型是指产品经理发现和设计的合理机制, 它能促成用户做出某种行为 (即交易), 且可持续 (生态是平衡的)。……拆解'利益创造'和'利益分配'两个词语, 交易模型的设计精髓就是'如何创造利益 (利从何来)'及'如何分配利益 (利往何去)'两个命题。"
> —— 3.1.2《什么是交易模型》

配套: "'产品即交易'里的'交易', 是指把人的任何有意识行为, 看作付出预期代价购买预期收益。" (2.5.1) / "同量的损失带来的负效用为同量收益的正效用的 2.5 倍。所以平均来说, 用户换回的物品或其他价值要大于支付代价的 2.5 倍, 交易才能成立。" (3.1.2) / "如果有一种制度安排, 使行为人追求个人利益的行为正好与企业实现整体价值最大化的目标相吻合, 这一制度安排就是'激励相容'。" (3.1.2)

## I — Interpretation (自述)

把"商业模式"重新表述为多边平衡的利益创造与分配机制。设计时回答两问: 利益从哪里被创造出来 (交换本身创造价值——没有等价交换, 双方都主观判断受益才成交; 新要素创造新价值; 降低交易成本释放被阻断的交易), 以及利益在各参与方之间怎么分 (分不好就有一方退出, 不可持续)。三个检验器: ① 损失厌恶——用户放弃的东西在他心里重 2.5 倍, 换回的价值不足 2.5 倍交易就难普遍成立; ② 激励相容——每方追逐自利的行为恰好推动整体目标, 而不是钻空子; ③ 长期弹性——短期数据好看但 12 个月后用户行为恶化的结构不可持续。企业层面, 一切行为围绕"让交换行为更多地发生", 行为权重按影响用户交换行为的 ROI 排序。

## A1 — Application Example (书中案例 / 合成演练)

【书中案例 · firsthand, 出处 4.4.3】滴滴拼车价值分配随供需重构: 价值总和 = 拼成共乘收益 – 未拼成折扣风险。供大于求时向乘客倾斜 (降司机单价+拼成奖励+自愿开关, 司机靠"在线时薪=计费时薪×计费时长占比"补回); 2018 下半年供小于求时向司机倾斜 (乘客两口价承担拼不成风险, 司机快车实时计价 + 共乘里程计价: 共乘收益=共乘里程×里程费单价×共乘倍率, 如 1 公里×1 元×0.5=0.5 元)。注意: 分配机制必须随约束条件 (供需状态) 切换。

【书中案例 · reported_case, 出处 3.1.3】西贝"不好吃不要钱"+服务员绩效与退菜数无关: 长期价值观落成可执行的分配规则 (风险由企业承担, 不转嫁一线)。

【合成演练 (原书未提供, 按其规则构造)】公司内部知识问答社区: 利从何来 = 提问者省时间 + 回答者获声誉 + 公司沉淀知识; 利往何去 = 声誉积分归回答者、公司担运营成本。激励相容检验: 匿名社区里回答者逐名行为与知识沉淀目标断裂 → 必须署名+积分可见。2.5 倍检验: 回答花 20 分钟, 需让声誉曝光 ≥2.5 倍感知价值 (首页展示/晋升参考)。

## A2 — Future Trigger (触发情境)

1. 设计或评审商业模式 / 商业化方案 ("这个生意怎么赚钱、能持续吗")
2. 多方利益冲突: 平台-供给方-用户-第三方谁多分谁少分 ("补贴给谁、抽成怎么定")
3. 机制/规则设计: 积分、分成、定价、准入、惩罚 ("怎么设计规则大家才都愿意玩")
4. 诊断"业务为什么做不长 / 一方在流失"

语言信号: "商业模式""利益分配""多边""生态可持续""激励""抽成 / 分成 / 补贴""规则设计""零和" (中英: business model, incentive design, multi-sided market, value distribution, sustainable ecosystem)

与相邻能力的区分 (阶段 3 定稿): 单个功能的用户价值评估用用户价值公式; 增长转化排查用相对价格公式; 本卡处理"多边利益结构与可持续性"。判责规则是本卡在纠纷子场景的特化 (见 dispute-liability-spring)。

**AI 产品化适配** (AI 适配, 非原书) 追加触发情境: ① "AI 产品的钱和责任在 用户-平台-模型供应商 之间怎么分"——多方交易表补模型供应商一方的得失; ② "用户数据/隐私/注意力拿去喂模型, 这笔账怎么算才可持续"——隐性支付显式定价。

## E — Execution (可执行步骤)

输入契约: 一项业务/产品 + 可列举的全部参与方 (用户细分、供给方、平台、合作方、监管等)。缺参与方清单时先补全 ("影响链上所有关联方"), 不默认只有买卖两方。

1. 画多方表: 每方写"付出什么 (钱/时间/供给/声誉风险) / 得到什么效用"。完成标准: 无一方"只得不付"或"只付不得"而不被解释。
2. 回答利从何来: 标注每笔价值创造的来源——交换创造 (双方主观受益差)、新要素、降低交易成本释放的增量。排除"零和转移" (从一方手里夺来的价值不算创造, 难持续)。
3. 回答利往何去: 逐方检查分配, 用三个检验器:
   - 2.5 倍: 每方换回的感知价值 ≥ 其付出代价的 2.5 倍? (不满足的方会退出或敷衍)
   - 激励相容: 该方追求自利的最优策略是否恰好是整体想要的? 找出可钻空子的策略并堵住或变堵为引。
   - 长期弹性: 该结构 12 个月后是否仍成立? 有无短期指标好看但透支信任的项 (对照医疗竞价排名反例)。
4. 标注约束条件: 当前的供需状态、文化、监管、阶段——并写明"约束变化到什么程度需要重新分配" (拼车两阶段示例)。
5. 输出: 多方利益表 + 三个检验器结论 + 重设计触发条件。

判停点: 发现核心价值来自零和转移且无新价值来源时, 如实输出"不可持续", 不用补贴掩盖。

输出契约: 多方利益表 (参与方×付出×所得×来源) + 检验器核对清单; 完成标准 = 三检验器逐项有结论。

**AI 产品化适配** 要点 (AI 适配, 非原书):
1. 多方表在 用户/平台 之外补两行: 模型供应商 (收 token 费、供能力、担模型缺陷改进) 与数据/内容提供方 (语料被使用, 收益或注意力是否回流); 各写"付出什么/得到什么"。
2. 把"用户以数据/隐私/注意力支付"的隐性项显式写进用户行付出列, 并过 2.5 倍检验: 用户换回的效用 ≥ 隐私感知代价的 2.5 倍吗? 不满足则该结构在透支信任。
3. 激励相容检查追加 AI 特有钻空子项: 平台是否有动机偷偷降级模型/压缩 token 以省成本而伤害用户体验? 有则设计可观测的质量承诺 (版本公示/质量指标)。
4. 把"模型成本/能力变动到什么程度需重新分配"写入重设计触发条件 (换模型、涨价、能力跃迁)。
5. 完成标准: 多方表含模型供应商行, 隐性支付项有标注, 三检验器均有 AI 语境结论。

## B — Boundary (边界)

- "产品即交易"是视角而非事实: 作者自承认与传统经济学交易定义不一致 ("更接近一种交换行为"); 用它分析无意识行为、强制场景无意义 (交易观以"没有强迫或欺诈的自由选择"为前提)。
- 2.5 倍是行为经济学平均系数, 不是精确阈值, 只用于量级感受。
- 分配机制强烈依赖约束条件: 拼车两阶段机制直接照抄到另一个市场 (文化/供需不同) 会错——任何输出必须附约束条件表。
- 内部数据 (滴滴订单、抽成) 未经外部核验 (needs-review nr-03), 引用时注明口径。
- 作者盲点提醒: 案例集中在双边出行平台; to B、硬件、内容创作类产品的多方结构不同, 检验器仍可用, 具体机制不可平移。
- 相邻易混: 判责/纠纷兜底的具体范式见 dispute-liability-spring; 边际结构分析见 marginal-analysis。
- **AI 产品化适配** (AI 适配, 非原书): 不要把"模型能力自然进步"记为本方创造的利——利从何来须答清本机制创造了什么交换增量; 拿用户数据训练的收益归属涉合规与信任, 不能只按平台自利一侧设计激励。
