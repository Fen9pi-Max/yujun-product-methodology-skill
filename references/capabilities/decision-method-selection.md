# 三种决策方法: 数据 / 逻辑 / 主观判断

## R — Reading (原文)

> "数据是这个时代最强大的工具。数据对于做产品的价值, 一般是作为做正确决策和达成共识的最低成本工具。……有了 AB 测试, 就可以事后选择已验证的更优策略。对于适合它的题型来说, 进行 AB 测试就是在偷看答案后解题。" (4.2.1)
> "逻辑决策也是'讲理决策', 结论靠逻辑推导得来。但需要对方具备相应的认知水平, 否则就会鸡同鸭讲。" (4.2.2)
> "主观判断决策是最难的决策, 没有数据或逻辑支撑, 只能用关键变量和用户模型、交易模型来模拟市场运行, 并据此做出判断。" (4.2.3)

## I — Interpretation (自述)

选决策方法先看手上有什么证据、对谁决策: 数据决策 (AB 测试/灰度) 成本最低且自带共识, 适合在线可控变量的选择题, 但有三个坑——不适合含重要线下环节的产品与硬件; 有卢卡斯批判式局限 (加总历史数据无视微观主体的适应反应); 找方向的开放题上失灵, 且会被"产品心弱者"当成偷懒工具 (只做能实验的事)。逻辑决策靠推导, 但说服力受对方认知结构刚性约束——你只能按对方的认知结构设计沟通, 补齐认知的成本极高。主观判断决策最难也最贵: 无数据无逻辑时, 用关键变量+用户模型+交易模型在脑中建临时模拟世界推演, 比较多个推演结果选最优; 配套思考习惯是"想法记下来→用过往经验证伪→不可证伪则假设成立存储→新信息来时提取匹配"。

## A1 — Application Example (书中案例 / 合成演练)

【书中案例 · reported_case, 出处 4.2.1】开市客 (Costco) 财报净利润≈会员费收入 → 有人归因"成功因为会员制", 差之毫厘谬以千里 (数据相关≠因果)。同节: 蓝海跑马圈地早期, 过度强调数据决策反而拖慢组织效率。

【书中案例 · firsthand, 出处 4.2.2】俞军劝阻一个业务, 最后说"凡是我反对但你坚持做的产品, 每一个都失败了", 对方答"那是因为产品经理没有好好做"——对方认知结构里没有三维归因, 用三维归因的"事实"无法沟通, 说服失败。

【合成演练 (原书未提供, 按其规则构造)】三任务配方法: a) 按钮文案改版 (在线高频) → 数据决策 AB; b) 说服 CFO 接受长期主义预算 → 对方认知结构是财务口径, 讲逻辑需换其语言 (NPV 化) 或借权威数据; c) 判断五年后新品类 → 主观判断: 列关键变量 (技术成熟度/供给成本曲线/政策), 用用户模型+交易模型推演两版未来, 证伪记录。

## A2 — Future Trigger (触发情境)

1. 争论"这事要不要做个 AB 测试" / "数据说明不了问题怎么办"
2. 需要说服不认同逻辑推演的人 (老板/合作方/客户)
3. 没有数据、逻辑也分歧的方向性判断 ("赌哪个方向")
4. 复盘"为什么我们被数据带偏了"

语言信号: "做个实验吧""数据不支持""说不通 / 他不听逻辑""拍脑袋""方向判断""预判" (中英: A/B test, data-driven, judgment call, no data available, convince stakeholders)

与相邻能力的区分 (阶段 3 定稿): 本卡回答"用什么方法决策"; 决策的整体质量结构 (信念-目标-行动+九视角) 见 rational-decision——两卡互为表里: 那张管"想得对", 这张管"怎么想"。推动他人接受结论的沟通技术另见 decision-landing。

**AI 产品化适配** (AI 适配, 非原书) 追加触发情境: ① "让 AI 跑一遍分析算不算数据决策"——AI 批量分析不改变题型判定; ② "AI 生成的行业报告能直接当决策依据吗"——按证据形式归类并核溯源。

## E — Execution (可执行步骤)

输入契约: 一个待决策问题 + 可用资源 (能否实验/有无数据/有无共同认知基础的对话对象)。

1. 判题型: 封闭选择题 (变量可隔离、可在线实验、周期短) 还是开放方向题? 含重要线下环节/硬件 (一年一迭代) 吗?
2. 匹配方法 (完成标准: 方法选择+一句理由):
   - 封闭+可实验 → 数据决策: 设计 AB (单变量、对照组、判停指标); 同步预注册解读口径防事后挑数;
   - 结论需他人接受 → 先判对方认知结构: 有共同认知基础才用逻辑决策; 否则换证据形式 (数据/案例/权威) 或先做小成本认知补齐, 不硬讲理;
   - 开放/无数据/逻辑分歧 → 主观判断决策: ① 列关键变量与约束; ② 调用用户模型+交易模型构建 2-3 个模拟情景推演; ③ 对每个推演做价值判断+风险概率判断; ④ 写成"假设卡" (记录→证伪→存储→新信息匹配)。
3. 标注方法局限进入交付物: 用了数据决策→列"哪些问题它答不了"; 用了主观判断→列关键变量清单供事后检验。
4. 输出: 方法选择记录 + 决策产出 + 局限声明。

判停点: 数据决策发现指标与机制解释矛盾 (如开市客式相关) → 停, 转机制分析, 不硬下结论。

输出契约: 方法匹配表 (问题/题型/方法/理由/局限) + 决策结果; 完成标准 = 每个决策都有方法理由与局限声明。

**AI 产品化适配** 要点 (AI 适配, 非原书):
1. AI 批量分析与模拟不改变题型判定: 封闭可实验题仍用 AB 实测, agent 只用于假设生成与结果解读; 开放方向题仍走主观判断路径, 不因"AI 出了报告"降级为逻辑题。
2. 对 AI 生成报告按证据形式归类: 有数据溯源的按数据证据核口径; 无溯源的只能记为"待验证的主观输入", 不得冒充数据决策。
3. 说服场景可用 agent 生成适配对方认知结构的版本 (财务口径版/案例版), 但进入交付物的关键数字须人工溯源。
4. 主观判断路径的"假设卡"可用 agent 辅助记录与新信息匹配, 关键变量清单仍由人定。
5. 完成标准: 方法匹配表的"方法+理由"栏注明 AI 参与部分及其证据等级。

## B — Boundary (边界)

- 数据决策: 不适合开放性大题、找方向、线下重的产品、硬件; 数据只反映过去; 卢卡斯批判——机械统计外推无视用户/企业的适应行为; 防止团队只做"能实验的事和老板关心的事" (脸书鄙视链警告)。
- 逻辑决策: "世界上不存在客观的事实"——对方不接受你的事实不是因为他蠢, 而是认知结构约束; 强行补齐认知成本极高, 多数时候应换证据形式而非加大逻辑音量。
- 主观判断: 必须已有用户模型/交易模型积累才能高质量推演 (作者: 台上三分钟台下三年功); 没有积累时它是赌博; 推演结论要可被事后检验 (记录关键变量)。
- 作者盲点提醒: 方法论默认高迭代可回滚环境; 低迭代业务中"快速实验兜底"失效, 预判与权衡权重需上调。
- 相邻易混: 决策整体结构用 rational-decision; 说服与推动用 decision-landing。
- **AI 产品化适配** (AI 适配, 非原书): 不要把"AI 总结了大量数据"等同于数据决策——AI 转述会引入幻觉与幸存者偏差, 卢卡斯批判对 AI 外推同样成立; 找方向的开放题上 AI 是推演工具, 不是答案来源。
