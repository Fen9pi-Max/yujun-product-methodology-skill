# 用户行为机制与五属性

## R — Reading (原文)

> "在行为发生前, 用户通常会接受一个情境的刺激, 这个情境的刺激会调用偏好和认知函数, 产生一个主观期望效用, 促使用户产生相应的行为, 即追逐这个预期的效用。而行为会产生某个结果, 这个结果又会成为经验, 影响偏好和认知函数。" (2.2.2)
> "用户有异质性、情境性、可塑性、自利性、有限理性这五个属性。" (2.2.1)
> "情境的刺激会激发感知、解读、选择集合、模拟推演、价值判断五步流程。" (2.2.2; 图 2-2 本体缺失, 以上为配套文字说明)

## I — Interpretation (自述)

用户行为的因果模板: 情境刺激 → 调用该用户的偏好与认知 → 经"感知/解读/选择集合/模拟推演/价值判断"五步 (常被系统 1 跳过若干步、且受认知偏误影响) 塑造出主观期望效用 → 促成行为 → 实际体验形成经验, 反过来修正偏好与认知 (下次行为就变了)。配套五个基本属性: 异质性 (没有两个一样的用户, 别统一画像)、情境性 (没有情境就没有用户, 同一人早高峰与雨天选择不同)、可塑性 (偏好可被信息刺激改变——营销与洗脑共用此机制)、自利性 (追求个人总效用最大化)、有限理性 (追求理性但能力有限、常出错)。两个操作推论: 偏好不变的人不同情境行为不同, 分析必须代入情境; 促成行为最省力的是"选对人" (偏好认知天然匹配), 否则才在情境五步上做设计。

## A1 — Application Example (书中案例 / 合成演练)

【书中案例 · reported_case (典故), 出处 2.2.2】望梅止渴: "口渴+谈论梅子"是情境, 认知里有"梅子酸" → 期望效用 (吃梅子解渴) → 行为 (向前行军找梅)。反事实: 没吃过梅子的人不产生期望效用; 吃到涩梅 → 经验反馈修正认知, 下次不追。

【书中案例 · 原书示例, 出处 2.2.1 / 1.3.3】情境性: 同一用户早上时间充裕时对时间确定性要求不高 (价格舒适权重升), 快迟到时时间确定性权重跃升; 可塑性: 传销洗脑、增长黑客利用人性弱点改变行为。

【合成演练 (原书未提供, 按其规则构造)】"用户领了优惠券却不用": 情境刺激 (领券即时推送) → 偏好认知 (怕麻烦/忘记) → 五步中"模拟推演"高估了使用意愿 → 行为 (闲置) → 经验反馈 (下次更不领)。干预点: 情境端到期提醒 + 缩短使用路径 (选择集合步), 而非加大面额 (期望效用步)。

## A2 — Future Trigger (触发情境)

1. 解释反直觉的用户行为 ("为什么用户不领情/领了不用/用一次就走")
2. 设计促活/促转化的干预点 ("在哪个环节推一把有用")
3. 评估用户研究结论的可迁移性 ("这个结论换个场景还成立吗")
4. 判断该"换人群"还是"改设计"

语言信号: "用户行为""为什么不转化""动机""情境 / 场景""偏好""认知""干预点""习惯养成" (中英: user behavior, context, preference, expectation, intervention point, why users don't act)

与相邻能力的区分 (阶段 3 定稿): 本卡是"行为如何发生"的机制模板 (诊断用); "如何长期积累成用户模型"见 user-model-accumulation (程序用); 增长杠杆的量化排查见 relative-price-growth。与通用行为设计 (福格模型等) 的区别: 以期望效用与偏好-认知函数为核心, 且强制五属性检查。

**AI 产品化适配** (AI 适配, 非原书) 追加触发情境: ① "用户为什么不信任我们的 AI"——一次幻觉体验如何经经验反馈压低期望效用; ② "用户什么都问 AI、该自己核验的也不核了, 怎么解释"——过度依赖是五步流程被系统 1 跳过的结果。

## E — Execution (可执行步骤)

输入契约: 一个目标行为 (想让谁在什么情境下做什么) 或一个待解释的实际行为。两者缺一不可——没有情境的行为描述无法分析。

1. 写机制链 (完成标准: 五环齐备): 情境刺激是什么 → 调用了什么偏好/认知 → 五步塑造中哪几步实际发生 (哪些被系统 1 跳过) → 期望效用多大 → 行为; 若是事后分析, 再加第六环: 实际体验如何反馈修正。
2. 五属性检查 (每项一句结论): 该行为在哪些人群间异质? 哪些情境变量改变结论? 可塑性被谁利用? 自利性指向什么总效用? 哪一步暴露有限理性 (偏误)?
3. 定位断点/干预点: 期望效用不足 (加效用) / 情境刺激没到 (改触达) / 五步被卡 (简化选择集合、降低模拟推演负担) / 经验反馈负 (先修体验再谈召回)。
4. 判"选人 vs 改设计": 若存在偏好认知天然匹配的人群 → 优先换/选人群 (原书: 最有效的方法); 不存在再投入情境设计。
5. 输出: 机制链图 (文字版) + 断点/干预点清单 + 选人-or-设计结论。

判停点: 无法写出具体情境与人群 (只有"用户一般会…") → 停, 先补样本, 防止在虚构的平均用户上做分析。

输出契约: 六环机制链 + 五属性检查表 + 干预点列表; 完成标准 = 链上每环有证据或明确标注假设。

**AI 产品化适配** 要点 (AI 适配, 非原书):
1. 解释 AI 不信任: 机制链写满第六环——一次幻觉/错误体验如何反馈修正偏好认知 (期望效用下调), 下次同类情境直接绕开; 干预点先修 bad case 体验再谈召回, 不靠宣传"模型很强"。
2. 解释过度依赖: 定位到五步流程被系统 1 跳过 (未做"模拟推演: 这个输出可能错吗"), 参照系从"自己查证"滑为"AI 说的"; 干预点在输出侧加低成本核验提示 (选择集合步), 不靠教育用户。
3. 异质性+情境性重判: 同一 AI 功能在高风险情境 (报税/就医参考) 与低风险情境 (闲聊/头脑风暴) 的信任行为完全不同, 分情境各出一条机制链。
4. "选人 vs 改设计"照用: 存在天然信任 AI 的人群 (AI 原生用户) 时优先选人, 否则才在情境五步上做设计。
5. 完成标准: 不信任与过度依赖各有一条五环齐备的机制链, 干预点标注落在哪一环。

## B — Boundary (边界)

- 机制是概率性模板不是决定论: 作者强调用户研究"只可归纳, 不可演绎", 机制链解释的是统计倾向, 不能精确预测具体个人。
- 意识不可直接测定, 只能经行为反推——机制链是解释工具, 断点定位是假设, 需用迭代验证 (接 user-model-accumulation 的预判-验证闭环)。
- 可塑性推论有伦理边界: 利用人性弱点操纵行为 (暗模式) 与创造价值的边界在"是否摧毁长期信任" (ce15), 本卡不提供操纵话术。
- 图 2-2 缺失: 机制以配套五点文字说明为据 (已如实记录), 未参考不可考的图形细节。
- 相邻易混: 长期积累与预判检验见 user-model-accumulation; 单次价值大小评估用 user-value-formula。
- **AI 产品化适配** (AI 适配, 非原书): 不要把不信任归因为"用户落后/不懂技术"——按本卡口径它是期望效用与经验反馈的结果; 也不要利用自动化信任做暗模式 (诱导用户盲信 AI 输出跳过核验), 那是可塑性推论的伦理禁区。
