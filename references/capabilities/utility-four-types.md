# 效用四分类: 底线 / 够用就好 / 越多越好 / 惊喜

## R — Reading (原文)

> "产品效用对用户需求的满足程度大体可以分为四类: 底线需求 (不能低于), 够用就好 (不用高于), 越多越好 (愿意多支付), 惊喜 (超过预期或参照系)。"
> —— 3.2.3《产品效用与用户欲望的不对等性》

配套: "每一个 bad case, 都是一次底线不满足。好事不出门, 坏事传千里……用户量大的服务型产品, 成长到一定阶段后, 应该追求的极致体验往往不是尽可能优质地满足用户需求, 而是 bad case 数量最小化。" / "把'够用就好'的需求打磨到边际回报率最划算的那个点就停下, 然后把'越多越好'的价值创造做到具有极高的投入产出比, 适量提供'惊喜'。"

## I — Interpretation (自述)

不是所有需求都值得做到最好。按"满足程度如何影响用户"分四类, 每类配不同投入策略: 底线需求是一票否决——低于门槛用户直接走, 所以大用户量产品的"极致体验"应重新定义为 bad case 数量最小化, 资源先去消灭最差体验而非拔高平均; 够用就好的需求满足度边际递减——技术指标好 5 倍用户可能无感, 打磨到边际回报划算就停; 越多越好类用户愿意多付——理论上做到边际收入=边际成本的均衡点; 惊喜是用户没有预期的增量效用——惠而不费, 是性价比极高的价值创造路径。关键提醒: 同一需求在不同用户、不同情境下属于不同类, 逐群判定, 不能全公司一刀切。

## A1 — Application Example (书中案例 / 合成演练)

【书中案例 · 原书示例, 出处 3.2.3】底线: 网约车司机不能有犯罪记录、夏天冷饮温度不高于某温度; 惊喜: 生日到餐厅吃饭, 餐厅送长寿面+全员唱生日歌。

【书中案例 · firsthand, 出处 3.4.7】滴滴专车 2016 年七八成司机认证、两三成未认证: 判定混合供给"得不偿失", 宁愿放弃两三成供给也要全认证——底线类 (安全确定性) 优先于供给量。

【合成演练 (原书未提供, 按其规则构造)】网约车功能分类: 安全 (底线: 一票否决+bad case 清零) / 车内气味 (够用就好: 无异味即停, 不做香氛分级) / 接单速度 (越多越好: 做到边际 ROI 均衡) / 生日优惠券 (惊喜: 少量高杠杆)。四问判类: 违反就流失? 做过头无感? 愿意为更多付钱? 用户本来没预期?

## A2 — Future Trigger (触发情境)

1. 资源分配争论: "这个方向还要不要继续投"
2. 质量指标设定: "体验要拉到多少分""验收标准定多高"
3. 排期取舍: 修长尾 bug 还是做新功能
4. 被批评"体验不够极致"时, 判断该类需求是否值得极致

语言信号: "做到什么程度""验收标准""优先修 bug 还是做功能""极致体验""边际收益""口碑事故 / bad case" (中英: how far to go, diminishing returns, must-have vs nice-to-have, delight, bad case)

与相邻能力的区分 (阶段 3 定稿): 本卡回答"做到什么程度"; "值不值得做"用用户价值公式; "增长卡在哪"用相对价格公式; 边际成本的具体算法见 marginal-analysis。与通用 must-have/nice-to-have 分类的差别: 以"满足程度的边际结构"判类 (一票否决/递减/递增/无预期), 且明确 bad case 最小化这一反直觉推论。

**AI 产品化适配** (AI 适配, 非原书) 追加触发情境: ① "AI 幻觉率/安全性要治理到什么程度才算够"——底线类按 bad case 最小化, 不按平均分; ② "这个 AI 功能是够用就好, 还是要越做越强"——按人群与情境判类后配投入档位。

## E — Execution (可执行步骤)

输入契约: 一份功能/需求清单 + 目标用户群 (或单条需求+人群)。缺人群定义时先补——分类随人群变化。

1. 对每条需求/功能, 依次四问判类 (完成标准: 每条有明确类别+一句依据):
   - 违反后用户会直接离开或造成传播事故吗? → 底线需求
   - 满足到某点后继续提升, 用户感知明显递减吗? → 够用就好
   - 用户愿意为更多满足支付更多 (钱/时间/数据) 吗? → 越多越好
   - 用户对该项没有预期, 做了是增量吗? → 惊喜
2. 按类配策略:
   - 底线: 定义不可逾越的门槛 + bad case 监控与清零机制 (优先级最高);
   - 够用就好: 设"够用线" (达标即停), 把过剩投入腾出;
   - 越多越好: 推进到边际收入≈边际成本的均衡点, 同时对比投入的机会成本;
   - 惊喜: 挑成本低感知强的项, 适量 (不过度抬预期, 抬高会变底线)。
3. 交叉核对人群: 抽 2-3 类细分用户重判一遍, 类别不同则分人群设策略。
4. 输出: 分类表 (条目/类别/依据/策略/投入档位)。

判停点: 若一条需求在"底线"与"越多越好"间摇摆且证据不足 → 按底线处理 (错配代价不对称: 底线当越多越好投会出事故, 反之只是浪费)。

输出契约: 四分类表 + 每条的投入档位建议; 完成标准 = 无未分类项、底线项均有监控方式。

**AI 产品化适配** 要点 (AI 适配, 非原书):
1. AI 功能判类先把"幻觉/安全/隐私泄露"按底线处理 (错配代价不对称): 列 bad case 清单 (事实错误/有害输出/数据外泄), 定监控口径与清零目标, 追求 bad case 数量最小化而非平均质量分提升。
2. 辅助生成类功能 (文案/摘要/初稿) 多为"够用就好": 设可接受错误率上限与达标线, 到线即停, 不为演示效果无限打磨。
3. 能力类功能 (检索质量/推理深度) 按"越多越好"推进到均衡点: 模型升级的边际收益 ≈ 边际 token 成本时停, 并对比投入的机会成本。
4. 跨人群重判不可省: 高风险情境 (医疗/法律/财务建议) 整体升为底线档, 低风险娱乐场景可放宽——同功能不同人群不同类。
5. 完成标准: 底线项有 bad case 监控方式与清零目标, 够用项有达标线, 越多项有均衡判据。

## B — Boundary (边界)

- 分类是手段不是标签: 同一需求跨人群/跨情境会换类 (书中明确), 输出必须绑定人群与情境, 禁止"全公司一刀切"。
- bad case 最小化适用于"用户量大的服务型产品成长到一定阶段后"; 小用户量产品或 to B 内部工具未必成立 (坏事传千里的传播机制弱)。
- 惊喜会抬预期: 反复提供同款惊喜会把它变成用户的预期 (滑向底线或越多越好), 书中"适量"即此意, 不可当成无限弹药。
- 作者盲点提醒: "越多越好做到边际收入=边际成本"在多边/补贴产品里因交叉网络外部性, 边际量难独立测得, 需借 marginal-analysis 并注明近似。
- 相邻易混: "整体产品是否有效用/有收益/可持续"用 product-value-judgment; 分类只处理满足程度的投入策略。
- **AI 产品化适配** (AI 适配, 非原书): 幻觉率不能只靠平均分/好评率评估——底线类要看最差 case 的分布与传播 (一次严重幻觉 = 一次底线失守); 反过来也不要把所有 AI 功能一律按底线拉满, 会挤占越多越好类的资源。
