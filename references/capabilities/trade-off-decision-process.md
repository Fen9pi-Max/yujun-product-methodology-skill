# 权衡决策流程: 本质拆解 → 约束条件 → 相对最优 → MVP → 迭代

## R — Reading (原文)

> "我们回归要解决的问题本质: 满足更快打到车的诉求。但'更快打到车'拆解下来包含了三层含义: 第一层是对何时能打到车有预期; 第二层是这个预期是否准确; 第三层是这个预期的时间是否还能更快。" (4.4.1)
> "从约束条件的差异分析, 首先是社会文化的不同。……然后是行业在社会中扮演的角色不同。……经过在特定环境下对公平和效率的权衡, 滴滴最终选择了以排队作为供需紧张场景下的主要解决方案。" (4.4.1)
> "在北京中关村进行的 MVP (最小可行产品) 实验, 验证了用户对于公平的感知和接受度。" (4.4.1) / "任何公式和抽象概念, 都要考虑约束条件。" (4.4.5)

## I — Interpretation (自述)

多方利益冲突时 (乘客 vs 司机 vs 平台 vs 公众), 高质量权衡有稳定套路: 先把诉求还原成可分层拆解的本质 (表面是"更快打到车", 实际是"有预期→预期准确→预期更快"三层, 各层解法不同); 再显式列出约束条件 (社会文化、行业公共属性、供需状态、平台阶段、既有规则)——同样的技术方案在不同约束下结论相反 (动态调价在欧美可行、在国内突破感性接受范围); 把道德/价值观命题翻译成效率与经济的权衡 (不是"谁对谁错"而是"哪种取舍整体最优"); 在约束下选相对最优解而非理想解; 从最紧张的场景切入做小成本 MVP 验证; 约束变化后重新设计而不是守着旧机制。该流程为从原书六个一手案例归纳的公共操作模式 (非作者命名的"五步法"原文, 卡内如实注明归纳性质)。

## A1 — Application Example (书中案例 / 合成演练)

【书中案例 · firsthand, 出处 4.4.1】动态调价 2 倍封顶后: 接受调价的人变多但运力没增, 大量用户付了钱仍打不到车, 投诉暴涨 → 回归本质三层拆解 → 约束分析 (国内排队文化 vs 国外价格接受度; 出行的公共属性) → 选排队 (先到先得给明确预期) → 中关村下班场景 MVP → 推广后继续迭代 (紧急需求优先: 用非金钱成本表达——会员每月几次应急优先+积分兑换, 不可积累定期清零, 防滥用)。

【书中案例 · firsthand, 出处 4.4.5】乘客中途改目的地: 对标出租车 (禁止拒载) 与"乘客>司机>平台"理念都不成立, 最终转成效率权衡——司机体验差→流失→运力成本升→摊到乘客头上; 各地供需不同需区别对待。

【合成演练 (原书未提供, 按其规则构造)】共享自习室占座之争: 本质拆解 (公平使用=可预期有座/预期准确/周转效率) → 约束 (学生占座惯例、高峰供需、监督成本) → 相对最优 (到店签到+离座超时释放, 非一刀切禁止) → MVP 一个自习区 → 按投诉与周转数据迭代。

## A2 — Future Trigger (触发情境)

1. 多方利益冲突需要定规则 ("乘客和司机吵起来了, 平台怎么判")
2. 好的技术方案落地后被骂 / 被文化抵制 ("为什么国外行得通我们不行")
3. 价值观争论僵持 ("到底公平重要还是效率重要")
4. 规则上线后环境变了, 要不要改

语言信号: "利益冲突""怎么权衡""A 和 B 打架""公平还是效率""规则怎么定""水土不服""试点一下" (中英: trade-off, stakeholder conflict, fairness vs efficiency, rule design, MVP, pilot)

与相邻能力的区分 (阶段 3 定稿): 本卡是"规则/机制怎么定"的流程; 纠纷判责的特定范式见 dispute-liability-spring (它是本卡在判责场景的特化); 决策质量结构见 rational-decision; 商业模式层的利益分配见 transaction-model-design。区别于通用决策流程: 本卡强制"约束条件显式化"与"价值观→经济权衡"两个翻译动作。

**AI 产品化适配** (AI 适配, 非原书) 追加触发情境: ① "AI 生成的 PRD/规则方案怎么评审"——按本流程补约束条件与价值观翻译两课; ② "和 agent 结对做多方案权衡, 分工怎么切"——拆解与候选可外包, 翻译与选优不外包。

## E — Execution (可执行步骤)

输入契约: 一个多方利益冲突问题 + 可识别的参与方。缺参与方或缺"表面诉求"时先补齐。

1. 本质拆解 (完成标准: 表面诉求被拆成 ≥2 层可独立求解的子诉求): "用户真正要的是什么"逐层追问, 每层写清"满足它的手段与其他层不同"。
2. 约束条件清单 (完成标准: ≥4 项, 含至少一项"为什么别人家的方案在这里不成立"): 社会文化 / 行业角色与监管 / 供需状态 / 平台或组织阶段 / 既有规则与习惯 / 技术与成本约束。
3. 价值观翻译: 把"应该不应该"的争论项改写成"哪种取舍在约束下整体最优"的效率-经济表述 (例: 公平 vs 效率 → 排队损失匹配效率换接受度与预期确定性)。
4. 生成候选方案并选相对最优: 不求理想解; 显式说明放弃了什么 (机会成本) 与谁会不满。
5. MVP 验证: 选最紧张/最典型场景, 定义可观测验证指标 (接受度/投诉率/满足率), 小范围试。
6. 迭代与重设计触发器: 写明"什么信号出现时要重新走第 2-4 步" (供需反转、文化变化、规模阶段跃迁)。
7. 输出: 权衡决策文档 (六节对应六步)。

判停点: 第 2 步发现关键约束信息缺失 (如不知当地供需) → 停下补数, 不带假设硬选; MVP 指标显著恶化 → 回炉而非加补丁。

输出契约: 权衡决策文档, 含分层拆解表、约束清单、价值观翻译句、所选方案+放弃项、MVP 指标、重设计触发器; 完成标准 = 六节齐备。

**AI 产品化适配** 要点 (AI 适配, 非原书):
1. agent 可承包的步骤显式划定: 本质拆解的候选层 (穷举子诉求)、约束条件初筛清单、候选方案批量生成; 每项产出标注"AI 生成待核"。
2. 人必须亲做的步骤: 价值观翻译 (哪种取舍整体最优) 与相对最优选择; 约束清单中"为什么别人家的方案在这里不成立"须由人写依据。
3. 评审 AI 生成的 PRD/规则时按本流程补课 (可核验): 逐条溯源第 2 步约束条件是否被 AI 遗漏或编造; 检查第 3 步价值观翻译是否被"行业最佳实践"话术跳过。
4. MVP 的验证指标口径由人定义, 不采默认建议。
5. 完成标准: 六节文档中 AI 生成内容全部有标注, 第 3-4 步 (翻译与选优) 有人写的决策理由。

## B — Boundary (边界)

- 五步框架是从原书六个案例归纳的操作模式, 不是作者亲笔命名的流程——引用时注明"由案例归纳", 不要伪称"俞军五步法"。
- 强约束依赖: 任何输出必须绑定约束条件表; 跨市场/跨文化照搬结论 (动态调价 vs 排队) 是该书反复警告的头号错误。
- MVP 依赖可观测指标与小成本试验窗口; 不可逆决策 (安全/法律/公关级) 不能靠 MVP 试错, 直接进入更重的前置推演。
- "价值观翻译为经济权衡"有伦理边界: 书中场景是商业规则设计; 涉及人身安全与底线的项 (如醉酒乘客安全) 作者并未货币化, 而是用犯罪铁三角阻断思路——不要把一切价值都换算成效率。
- 内部数据未经外部核验 (nr-03); 表 4-1 内容缺失, 拼车演变链仅两阶段可考 (nr-01)。
- 相邻易混: 判责/兜底专项见 dispute-liability-spring; 单产品价值评估不涉及多方规则, 用 user-value-formula。
- **AI 产品化适配** (AI 适配, 非原书): 不要把 agent 生成的"完整权衡文档"当成权衡已发生——输出完整不等于约束被真实列出; AI 编造的约束/数据若未溯源, 后续 MVP 会在错误问题上消耗验证预算。
